# Проверка резервного копирования — 26 октября 2026

На VPS `157.22.174.79` восстановлен ежедневный бэкап «Карточек».

- `kartochki-backup.timer`: ежедневно 03:15–03:20 Europe/Moscow, с догоняющим запуском после простоя.
- `kartochki-backup.service`: пользователь `arzhannikov_bot`, защита от одновременного запуска.
- Состав: PostgreSQL, `/app/storage`, версии образов, дата и контрольные суммы.
- Локальное хранение: `/opt/kartochki/backups/complete`, 14 дней; отдельные дампы БД — `/opt/kartochki/backups/postgres`.
- Внешнее хранение: `yandex_disk:kartochki-online/complete`, 30 дней. Второй VPS не используется.
- Полные архивы зашифрованы age на публичный SSH-ключ владельца. Приватный ключ остаётся локально у владельца.
- Перед отметкой успеха архив читается с Яндекс Диска и сверяется SHA256. При ошибке старые полные архивы не удаляются.

Используется собственное OAuth-приложение «Карточки — резервные копии» с правами Disk read/write/info.
У общего клиента rclone файловые запросы возвращали 410; WebDAV нестабильно принимал загрузки.
Рабочая конфигурация API имеет права 0600, принадлежит deploy-пользователю и сохранена в GitHub Secret
`YANDEX_DISK_API_CONFIG`. Публичный получатель сохранён в repository variable `BACKUP_RECIPIENT`.
Клиент rclone 1.75.2 установлен отдельно от системного после проверки SHA256 официального архива.

Первый успешный запуск завершился **26 октября в 01:36:32 МСК**:

```text
kartochki-complete-20261025T223529-3521188.tar.gz.age
SHA256 062e830bdbdcc1670e08c9f2a087265f13ed0b5bdbb0135ba6091aedbad54693
```

Проверки финальной копии:

- Выгрузка и чтение с Яндекс Диска завершились успешно; SHA256 совпал.
- Архив расшифрован локальным ключом владельца, внутренние контрольные суммы совпали.
- БД восстановлена в изолированном PostgreSQL 17 без сети и с временным хранилищем: **27 таблиц, 872 строки**; количества совпали с рабочей БД.
- **150 файлов** из архива совпали с рабочими файлами по SHA256.
- Временный PostgreSQL удалён после проверки; рабочая БД не изменялась.
- CI проверяет синтаксис и обработку сбоев дампа, шифрования, загрузки и сверки контрольных сумм.
- Главная страница возвращает HTTP 200, API health возвращает `ok`.

Для восстановления нужен приватный ключ, соответствующий `/opt/kartochki/backup-recipients.txt`:
текущая проверка выполнена с локальным `~/.ssh/id_rsa`. Инструкции восстановления и границы
копирования (включая отдельное восстановление очередей Redis/Asynq и конфигурации) описаны в README.
Внешние уведомления об ошибках не подключены; состояние видно в systemd и файле `last-success`.
